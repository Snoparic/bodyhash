# bodyhash

[![Forgejo](https://img.shields.io/badge/Forgejo-main-blue)](https://git.snoparic.su/snoparic/bodyhash)
[![GitHub](https://img.shields.io/badge/GitHub-mirror-black)](https://github.com/Snoparic/bodyhash)
[![GitFlic](https://img.shields.io/badge/GitFlic-mirror-green)](https://gitflic.ru/project/snoparic/bodyhash)

Утилита для вычисления хеша тела файла с исключением заданных областей (например, шапок с метаданными).

По умолчанию `bodyhash` нормализует концы строк (CRLF -> LF), удаляет UTF-8 BOM и убирает пробелы в конце строк. Это гарантирует, что хеш не изменится при переносе репозитория между Windows и Linux.

## Кроссплатформенность

`bodyhash` работает на Linux (GNU coreutils), macOS (BSD userland), а также в Git Bash и WSL:

* нормализация выполняется целиком в POSIX-awk, GNU-специфичные escape-последовательности sed не используются;
* весь awk и grep вызываются с `LC_ALL=C`: хеши одинаковы при любой системной локали и любой реализации awk (gawk/mawk/BSD/busybox) — в UTF-8-локалях gawk иначе считает BOM одним символом и байтовое срезание молча ломается;
* бэкенд хеширования выбирается автоматически: `sha256sum`/`sha512sum`/`md5sum`/`b2sum` (GNU) -> `shasum`/`md5` (macOS/BSD) -> `openssl dgst` (fallback; всегда используется для `sha3-*` и `blake2s`);
* для разворачивания табов используется `expand`, при его отсутствии — встроенный awk-аналог с той же математикой таб-стопов;
* результат хеширования не зависит от выбранного бэкенда: алгоритм задаёт дайджест однозначно.

## Установка

Требуются права root для записи в `/usr/local`:

    sudo make install PREFIX=/usr/local

## Использование

    bodyhash <команда> [аргументы] [опции]

### Команды:
*   `hash <file>` — вывести хеш тела файла.
*   `check <file> <hash>` — сравнить хеш тела файла с ожидаемым (код возврата 0, если совпадает; регистр букв хеша не важен).
*   `markers <file>` — показать номера строк, где найдены указанные маркеры.

### Основные опции:
*   `-e, --exclude "НАЧАЛО::КОНЕЦ"` — исключить блок между литеральными маркерами (обе строки-границы тоже исключаются; опцию можно повторять, вырезаются все блоки каждой пары).
*   `-a, --algo <algo>` — алгоритм (`sha256` по умолчанию, также `sha512`, `sha3-256`, `sha3-512`, `blake2b`, `blake2s`, `md5`).
*   `--no-normalize-crlf` — не трогать концы строк.
*   `--no-strip-bom` — оставить BOM.
*   `--no-strip-trailing-ws` — оставить пробелы в конце строк.
*   `--strip-leading-ws` — удалить пробелы в начале строк.
*   `--indent-tabs=N` — заменить табы на пробелы до следующего кратного N столбца.
*   `--exclude-preamble` — игнорировать всё до первого маркера.
*   `--exclude-epilogue` — игнорировать всё после последнего маркера.
*   `--strict-start` — требовать, чтобы маркер `START` был на первой строке.

### Коды возврата:
| Код | Значение |
|-----|----------|
| 0 | успех |
| 1 | хеш не совпал (только `check`) |
| 2 | ошибка аргументов, неверный формат `-e`, сработал `--strict-start` |
| 3 | пара маркеров не найдена (в т.ч. незакрытый блок `START` без `END`) |
| 4 | файл не найден |
| 5 | внутренняя ошибка |
| 6 | неизвестный алгоритм или нет подходящей утилиты хеширования |

Каждая указанная пара `-e` обязана найтись в файле, а каждый `START` — закрыться своим `END`: иначе `bodyhash` завершится с кодом 3, а не посчитает хеш «молча».

### Примеры:

    # Хеш тела C-файла (игнорируя шапку между /** и */)
    bodyhash hash file.c -e '/**::*/'

    # Проверка
    bodyhash check file.c 1857616f15bd53f72c1733a1839421116c7bbb50579f2cdb9ceca9adfcd30fda -e '/**::*/'

    # Несколько пар маркеров: метаданные и volatile-блок
    bodyhash hash file.conf -e '[META::[/META]' -e '<volatile::</volatile>'

## Тестирование

    make ci        # bash -n + shellcheck (если установлен) + bats

Тесты используют `./bodyhash` из рабочей копии, установленный бинарник не нужен.
